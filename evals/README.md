# 对镜 · 评测集

> 回答一个问题：**改了 prompt，怎么知道是变好了还是变坏了？**
>
> 在此之前这个项目答不上来。`tests/test_ai_layer.py` 测的全是管道
> （路由对不对、JSON 能不能抠出来），**没有一条在评估模型输出的质量**。

---

## 两层结构（为什么不在 CI 里跑 judge）

| 层 | 跑什么 | 花不花钱 | 在哪跑 | 证明什么 |
|---|---|---|---|---|
| **规则校验** `checks.py` | schema、观察上限、废话黑名单、长度、复盘块非空 | **免费**（`AI_PROVIDER=mock`） | **CI**（每次提交） | **管道没坏** |
| **LLM-as-judge** `judge.py` | 具体性 / 有无依据 / 可执行性 / 是不是废话 | 要真实 Key，几毛钱 | 本地或服务器**手动** | **观察准不准** |

**为什么 judge 不进 CI**：它花钱、要密钥、且模型输出本身有方差。
把这三样塞进 CI，得到的是一堆 flaky 红灯和一个公开仓库里的 API Key。
CI 该当的门禁是**确定性**的，judge 该当的是**质量报告**。

> ⚠️ **必须说清规则层的局限**：用 Mock 跑时，模型对每场辩论返回的是同样的几条罐头观察，
> 所以 12/12 通过**只说明管道是通的**，不说明观察是对的。
> 真正区分「模型有没有在读内容」的是 judge 层的 `repeated_observations` ——
> 12 场不同的辩论如果抽出同样几条观察，那就是在套模板，一眼能看出来。

## 用法

```bash
# 规则校验（免费、确定性）
python -m evals.run --mode rules

# 规则校验 + judge 打分（需要 Key）
python -m evals.run --mode judge

# judge 单独重跑 —— 读已有的规则层报告，不重新跑生成
python -m evals.judge --report evals/reports/rules-<时间戳>.json

# 只跑前 3 条，调试用
python -m evals.run --mode rules --limit 3
```

报告写到 `evals/reports/`（**不入库**，与 e2e 的产物同样处理）。

### 为什么 judge 要能单独重跑

这不是洁癖，是**被真实事故逼出来的**：

第一次在服务器上跑时，进程在规则层跑完、刚进入 judge 的那一刻**静默死掉**
（非 OOM，内核无记录、内存充裕、生产服务与数据完好，原因至今未定位到）。
而当时报告是在 judge 之后才写的 —— 于是 30 条规则层的结论**一起丢了**，
只能从头再跑一遍，白花一次钱。

改成了两件事：

1. **规则层报告先落盘**，再跑 judge。跑了几分钟的成果不该由一个后续步骤决定去留
2. **judge 独立成一条命令**，只需要 golden set + 已产出的观察，不重跑整个 App；
   而且**每判完一条就写一次中间文件**，再崩也不会全丢

用 `--mode judge` 时若 judge 中途失败，规则层报告已经保住了，
按上面第二条命令单独重跑 judge 即可。**生成那部分的钱不会白花第二次。**

### judge 用哪个模型

默认 **DeepSeek**，可用 `EVAL_JUDGE_PROVIDER` 改。

**为什么必须和被测模型不同**：被测的观察提取走 MiMo（方案 5.3 的路由），
裁判如果也用 MiMo，等于让同一个模型给自己打分，系统性偏袒无法被发现。

### judge 自己也有偏见

所以：分数**只做相对比较**（改 prompt 前后跑同一套），不当绝对真理；
报告里同时给出废话条数、错标条数、以及**跨用例重复的观察**——
最后一个不需要任何评分就能说明问题。

## golden set

`evals/golden/observations.jsonl`，一行一条：

```json
{"id": "arg-01", "layer": "论证结构", "topic": "...", "stance": "该",
 "user_turns": ["第一轮发言", "第二轮", "第三轮"],
 "forbid_substrings": ["你很棒"]}
```

- `layer` 必须是方案 3.1 的四层之一：论证结构 / 情绪与防御 / 互动策略 / 语言习惯
- `user_turns` **至少 3 轮**：两轮发言观察不出「互动策略」或「语言习惯」，那是编的
- 四层必须都有覆盖（`tests/test_evals.py` 会守）

### 当前是**合成数据**

没有用生产里的真实辩论记录。真实的更可信，但需要脱敏 + 人工标注。
合成数据的用途是**先把评测流程跑通、把基线量出来**；
面试时被问「样本从哪来」要如实说是合成的，不能含糊。

## 实测结果：prompt v1 → v2 → v2.1 → **v2.2**

同一套 golden set、同一个裁判（DeepSeek，被测走 MiMo，换源避免自评）。

**v2.2 这一列是三次重复运行的均值**（单次运行的方差比想象中大，见下节）：

| 指标 | v1 | v2 | v2.1 | **v2.2（3 次均值）** | 相对 v2.1 |
|---|---|---|---|---|---|
| 具体性（5 分制） | 3.26 | 3.86 | 4.22 | **4.08**（3.96–4.19） | −0.14 |
| 有依据（5 分制） | 3.51 | 3.88 | 4.42 | **4.17**（4.02–4.26） | **−0.25** |
| 可执行性（5 分制） | 2.40 | 2.92 | 3.27 | **3.10**（3.02–3.19） | **−0.17** |
| 判为废话 | 13 条 | 6 条 | 2 条 | **1.0 条**（0/1/2） | −1 |
| 判为错标 | 16 条 | 7 条 | 5 条 | **6.3 条**（5/6/8） | +1.3 |
| 完成打分 | 24/30 | 28/30 | 28/30 | **29.0/30** | +1 |
| 规则层通过率 | 100% | 96.7% | 100% | **100%**（3/3 次） | 持平 |
| **跨用例重复的观察** | 3 类 | 2 类 | 0 类 | **0 类**（3/3 次） | 持平 |
| 成本 | 0.0691 元 | 0.0852 元 | 0.0895 元 | **0.0881 元** | −1.5% |

prompt 长度（复盘 system）：402 → 1297 → 1707 → **2167** 字符。

## ⚠️ 重复三次之后，上一版的三个结论要更正

v2.2 的改动只有一个：**复盘不评判对错，只描述模式**（同时辩论人格从「对手」改成「陪练」）。
第一次跑完时我写了单次结果和三条结论 —— 补齐两次重复后，**其中三条站不住**。如实记下来：

### v2.2 三次重复的原始数据

| 运行 | 具体性 | 有依据 | 可执行性 | 废话 | 错标 | 完成 | 成本 |
|---|---|---|---|---|---|---|---|
| 第 1 次 `judge-20261018-134314` | 4.08 | 4.24 | 3.08 | 0 | 6 | 29 | 0.0856 元 |
| 第 2 次 `judge-20261018-140345` | 4.19 | 4.26 | 3.19 | 1 | 5 | 28 | 0.0876 元 |
| 第 3 次 `judge-20261018-141127` | 3.96 | 4.02 | 3.02 | 2 | 8 | 30 | 0.0912 元 |
| 均值 ± 标准差 | 4.08 ± 0.12 | 4.17 ± 0.13 | 3.10 ± 0.09 | 1.0 | 6.3 | 29.0 | 合计 0.264 元 |

**同一条 prompt、同一套用例，具体性在 3.96–4.19 之间波动（跨度 0.23）。**
单次运行的差异有一半是噪声 —— 这正是「必须重复」的直接证据。

### 用 σ 衡量，三个质量分的结论完全不同

把 v2.1 的单次值与 v2.2 的均值比，用 v2.2 的标准差折算：

| 指标 | v2.1 | v2.2 均值 | 差距 | 折算成 σ | 结论 |
|---|---|---|---|---|---|
| 具体性 | 4.22 | 4.08 | −0.14 | **1.24σ** | **不能判定**（在噪声内） |
| 有依据 | 4.42 | 4.17 | −0.25 | **1.86σ** | 倾向下降，边缘 |
| 可执行性 | 3.27 | 3.10 | −0.17 | **2.01σ** | **下降可信** |

### 三条结论的更正

| 上一版的说法 | 更正后 |
|---|---|
| 「三分数各降 3–6%」 | 只有**可执行性**超过 2σ；**具体性在噪声内**；有依据边缘 |
| 「**废话清零**」 | **站不住**：三次是 0/1/2，均值 1.0 条。比 v2.1 的 2 条好，但**不是清零** |
| 「成本降 4.4%」 | 用 3 次均值是 **−1.5%**（单次 0.0856 那次正好是三次里最低的） |

**这几条更正的共同点：都是「拿单次运行当结论」。** 第一次跑出 4.08 就写「下降 3.3%」，
第二次同一份代码就跑出 4.19 —— 差 0.11，和所谓「下降」是同一个量级。

### 这个结论本身还有一个保留

**v2.1 只有单次运行。** 它自己也可能是一次偏高或偏低的结果。
严格的做法是 v2.1 也跑 3 次 —— 但那需要把辩论人格（代码里的 `FIXED_SYSTEM_PROMPT`）
一起回退，`REVIEW_PROMPT_VERSION` 环境变量只能切复盘 prompt、切不动人格。
所以这里只能说「**可执行性的下降比另外两项更可信**」，不能说「v2.2 确实变差了」。

## 可执行性为什么一直是最低分：一个**口径问题**

拆开看每条观察的 `actionability` 之后发现一件事：**优势观察系统性地拿 2–3 分**。

```
arg-01 weakness  act=4 | 第2、4轮重复立场未展开论证
arg-01 advantage act=3 | 第2轮以对项目负责立论
lan-02 advantage act=2 | 引用车与池子类比作证
emo-01 advantage act=3 | 第2轮先复述对方问题再回应
```

原因不在生成质量，在**裁判的问题问错了对象**：

- judge 的 rubric 是「用户看完能**改变什么具体行为**？5=知道下一步做什么」
- 而它把这个问题问了**观察标签**（`weakness.name` / `advantage.name`）
- 一条优势观察（「引用类比作证」）本来就不该告诉用户「下一步做什么」——
  **产品设计里「下一步做什么」是由复盘卡片的 `alternative_action` 承担的**

所以从 v1 起 `actionability` 就是四项里最低的（2.40 → 3.27 → 3.10），
**其中有多少是质量、有多少是口径，目前分不开。**

这是下一步要做的**决策**，不是能顺手改的 bug：

| 选项 | 做法 | 代价 |
|---|---|---|
| A | 把 `actionability` 改问「复盘卡整体（含 alternative_action）」 | 与前三轮的历史数字**不再可比**，要重跑基线 |
| B | 只对 weakness 观察打这个分，advantage 不打 | 改动小，但需要重算历史均值（原始报告都留着，可以重算） |
| C | 承认它就是结构性低分，不追 | 省事，但等于放着最弱的指标不管 |

**当前先不动评测口径** —— 换尺子会让「v2.2 变差了多少」这个问题失去参照。
先把口径问题记在这里，等产品决定。

---

**最有力的证据不是分数，是这三条：**

1. v1 对几乎每条辩论都只回「回避追问」+「立场坚定」——它在套两个万能标签，
   根本没在读内容。v2 之后能识别出 golden set 里**设计好的**模式：
   循环论证 → 「循环论证未察觉」；以偏概全 → 「个案当定律」；
   绝对化措辞 → 「用绝对化措辞代替论证」。
2. **v2 起有 5 条用例主动不给优势**（v1 只有 1 条）。那几条本就是
   「只有弱点、没有对应优势」的设计 —— v1 会硬编一个「立场坚定」，
   v2 会说「没有依据」。**敢说没有，才是真的在读。**
3. v2.1 把**跨用例重复降到 0** —— 30 场不同的辩论，再没有两条抽出同样的观察。
   v2.2 的三次运行也都是 0 类。

### 三段迭代各自改了什么

| 版本 | 改了什么 | 为什么 |
|---|---|---|
| **v2** | 补四层定义；写清「什么不算观察」+ 一条自检；`reason` 必须原样引用用户原话 | 看基线数据定位：v1 通篇没提四层（16 条错标的主因）；只说「不要泛泛而谈」却没说**什么算**；优势侧零约束 |
| **v2.1** | 把「没依据给 null」**限定在两条观察上**，三个叙事块反过来必须写 | **v2 自己引入的回归**：规则层 100%→96.7%，arg-01 的 `next_time` 变空。严格性外溢到叙事块，模型连「下次怎么改」都不写了 |
| **v2.2** | 追加「不评判对错，只描述模式」整段；辩论人格同时从「对手」改成「陪练」 | **真实用户反馈**：「AI 太强，把我变成了被审判者」。原 prompt 没禁止评判，模型自然写成评估报告口吻 |

### ⚠️ 这一节最该被看到的是 v2 的代价

**只看 judge 的三个分数，会得出「v2 全面变好」的结论 —— 那是错的。**

v2 的质量分确实全面上涨，但它同时让复盘卡片的「如果再来一次」那一栏变成空白。
**那个空块只有规则层能抓到。** 这正是两层设计存在的理由：
确定性检查和质量评分**互相看不见对方的盲区** ——
`next_time` 为空是硬伤，但它不表现为「分数下降」，
它表现为一个用户打开就皱眉的空白栏，而 judge 根本不看叙事块。

**v2.1 修好之后，规则层回到 100%，同时质量分继续上涨。**

### 仍未解决

judge 自己有 **1/30 条返回了非法 JSON**（本轮是 int-03；v1/v2/v2.1 是 arg-01、int-01）。
这是 **judge 层的健壮性问题**，与 prompt 无关：应该换成 `app/ai/structured.py` 那套
「schema 校验 + 失败重试一次」，而不是直接 `extract_json`。
**如实记在这里，不掩盖** —— 一个评测工具自己有 3–7% 的失败率，报数时就该说清楚。

另外，本轮报告里 `repeated_observations` 是空对象 `{}`（表示「无重复」），
和之前几轮的展示形式不同；这是 `judge.py` 在「零重复」时的输出形态，不是漏算。

## 评测集自己也会坏

**一个永远返回「通过」的评测，比没有评测更危险**——它让人以为有保障。

所以 `tests/test_evals.py` 守三件事：

1. golden set 每条都写对了（字段齐、层合法、发言够多、id 不重复）
2. golden set 有覆盖（四层都有，且不是同一条复制十遍）
3. **规则函数真的会失败** —— 每条规则都配了「故意违规必须被抓到」的反向用例

第 3 条最容易被忽略：如果 `check_observations` 因为一个拼写错误永远返回通过，
普通测试套件不会有任何反应。

## 怎么用它回答面试问题

> **「你改了 prompt，怎么知道效果变好了？」**

1. 跑 `--mode rules` 拿到硬错误基线（免费）
2. 跑 `--mode judge` 拿到质量基线：具体性 / 依据 / 可执行性 / 废话条数
3. 改 prompt
4. 两层各再跑一遍，对比报告
5. 报告里贴的是**两张表**，不是一句「感觉好多了」

这也是**失败样本回流**的入口：judge 判低分的那些用例，就是下一轮要改 prompt 的依据。
