## 二、P0：撑住率「无数据」不再显示为 0%

### 问题

```python
def hold_rate(hold, total):
    if total <= 0:
        return 0        # ← 这里
```

新用户建完第一个回环、**一次都还没练过**时，看到的是「撑住率 0%」。
而 0% 的含义是「你每次都失败」。

### 修法：在类型层区分，而不是靠前端判断

`hold_rate()` 现在返回 `int | None`。选数据层而不是展示层，是因为
**任何新的消费方都可能再次误读**——展示层修一次只解决一个页面。

| 值 | 含义 | 呈现 |
|---|---|---|
| `null` | 还没有触发记录 | `--`　中性色　「还没有记录」　进度条只画空槽 |
| `0` | 真的每次都破功 | `0%`　砖红 `--rate-low`　实心填充 |

数字、颜色、无障碍标签三处都可区分；只记过「未触发」时仍算无数据（不进分母）。

顺带修了「今天练什么」的排序：**无数据的回环排最前**——对新建回环的用户
来说它是唯一一条，必须出现。

## 三、P0：两个空状态从「告知」变成「带领」

### 改造前

新用户注册后看到四个空分区，每个都只有一句克制的说明文案。
他知道「这里现在是空的」，但不知道**下一步该做什么**。

### 改造后

| 卡片 | 文案 | 行动 |
|---|---|---|
| 今天练什么 | 想不想来一次 3 分钟的即兴辩论？<br><small>不用准备，选个立场就能开始。</small> | **开始** → 面板随机出一题 → 两个立场按钮 → 进辩论房 |
| AI 观察 | 记录一个你今天不爽的瞬间，AI 帮你看看盲区。 | **记一笔** → 只有一个输入框 → 保存 |

**从首页到开始一场辩论只需要 2 次点击、零输入。**

辩题池 10 题，全部满足「零背景知识、任何人都有话说、两边都站得住」：


## 四、P1：趋势（回答「我在变好吗」）

弱点与回环详情的撑住率旁显示「较上周 ↑/↓ N%」。

**任一周没有触发数据时 `trend_delta` 为 `null`，前端不显示趋势**——
显示「↑ 0%」会制造「我在原地踏步」的错觉，比不显示更糟。

## 五、P1：预约辩论提醒 + Web Push

方案 3.9 规定「默认不推送，唯一例外是用户主动预约的辩论提醒」。
这句话的分量在于：**推送权是用户借给我们的**，只能用在**他自己约的那个时间点**上。
这条原则写进了 `app/services/push.py` 的模块注释，防止后来者用它去「顺便提醒一下还没记录」。

| 环节 | 实现 |
|---|---|
| 预约入口 | 辩论房操作栏「提醒我」，5 个预设时间点（今晚 8 点 / 明晚 8 点 / 30 分钟后…） |
| 无设备时 | **面板不关闭**，明确提示「已记下，但还没开启通知」——不能让用户以为约好了却收不到 |
| 推送 | VAPID + Web Push，Service Worker 经 `workbox.importScripts` 注入 |
| 定时 | 每分钟扫一次待发提醒（空查询成本极低，但不能晚到——约了 8 点，8 点 05 才响就已经失信） |
| 失效清理 | 推送服务返回 404/410 时标记订阅停用，不再重试 |
| iOS | 未「添加到主屏幕」时给出具体操作路径，而不是笼统说「不支持」 |

## 七、顺带修掉的一个真实冷启动阻塞

**注册页硬性要求填写邀请码**，但只有**第一个用户**能免邀请码注册——
而部署者第一次打开自己的站点时，手上不可能有邀请码，因为能发码的人还没注册。

新增公开端点 `GET /api/auth/bootstrap`，注册页据此自适应：

- 实例为空 → 隐藏邀请码字段，文案改为「你是这个实例的第一个用户，直接注册即可」，按钮改为「创建账号」
- 已有用户 → 维持邀请制不变

测试同时守住「已有实例仍必须凭码注册」，确保没有把邀请制放开。

## 十一、追加：首页条件渲染（底部按钮去重）

### 需求

全新用户阶段，底部两组全局快捷按钮与卡片内的行动重复：
「和 AI 辩一轮」≈「开始」，「+ 记一笔」≈「记一笔」。
同屏两个主色按钮会稀释「一个明确的行动」。

### 实现

| 状态 | 卡片内边距 | 底部按钮 | 收尾文案 |
|---|---|---|---|
| 全新用户 | 加宽（`py-8` / `pb-9 pt-6`） | **隐藏** | 「这是你的第一站」（极淡灰） |
| 已有数据 | 常规 | 显示 | 无 |

### 判定逻辑：比字面要求更严一点

需求原文是「两张卡片同时为空就隐藏」。但那样**「记一笔事件卡」不会让按钮回来**——
事件卡既不建回环、也不立即产生 AI 观察（它先进队列，等夜间扫描），
所以记了几笔的用户在首页上仍然长得像全新的，而他明明已经在用了。

因此判定条件收紧为：**两张卡片都空，且从未留下任何痕迹**
（事件卡 / 辩论 / 弱点 / 演练日志，任一存在即不算全新）。
由服务端计算 `is_fresh_start` 下发，前端不自己拼。

`TestFreshStart` 里「记事件卡后两张卡片仍为空但已不算全新用户」
是关键用例，防止后人把判定简化回字面版本。

## 十二、第一次真实使用记录

2026-09-26 11:43，部署者本人走完了完整的冷启动路径：

```
11:43  首页「开始」→ 面板出题 → 选立场 → 创建辩论
       辩题：别人夸你，该不该当真？
11:43  AI 开场立论（DeepSeek）
11:47  用户发言（真实、认真的一段论证）
11:47  AI 回应
```

值得记下来的是 AI 那两句的质量——它没有停留在「你说得也有道理」，
而是直接指出了论证里的问题：

> 你这个改法其实比原型场聪明——但聪明在于，你悄悄放掉了原型场。
> 「当真」是把它接受为对我的定论。而你说的「看明天怎么说、细心居多就算优点」，
> 是你自己在收集、比较、下结论。夸奖在你手里只是数据，判断权始终没交出去。
> 这叫参考，不叫当真。**你自己已经站到我这边了。**
>
> 再说统计法本身：夸你的人是自选的……那些说你粗心的人，
> 可能就是被你多数票筛掉的真话。**多数不等于真相。**

这印证了两件事：
1. 冷启动路径是通的——一个刚打开产品的人，两次点击就进入了真实辩论
2. `FIXED_SYSTEM_PROMPT` 里「论证结构：是否偷换概念」这条观察要求，
   模型确实在辩论过程中执行了（虽然观察按设计只在复盘时输出）
