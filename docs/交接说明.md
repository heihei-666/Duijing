## 3. 我做了什么

### 3.1 修复「结束并复盘」够不着（09-26，`480cf1d`）

你当时的原话：*「辩论达到 7 次，有弹窗提示我可以点击结束并复盘，但是好像没有对应的按钮或者其他可操作的。」*

查下来不是按钮不存在，而是**指路指到了屏幕外**——一共四个问题：

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 提示说能点，但点不到 | 操作行在消息列表顶部且**刻意不吸顶**（避免一进房间就被按钮占掉半屏），辩到第 8 轮时它离底部好几屏；提示文字却在底部粘性输入区 | `DebateComposer` 新增 `noticeAction`，提示条右侧就地渲染按钮 |
| 2 | 刷新后提示直接消失 | 提示靠 SSE `done` 事件临时 `setNotice`，不持久 | 改由**房间状态推导**（`composerNotice`） |
| 3 | 每轮重复唠叨 | `is_last_round = current_round >= max_rounds`，辩到第 8 轮弹了 5 次 | 去掉事件式唠叨，由常驻提示条表达 |
| 4 | 顶栏显示「第 8 轮 / 共 4 轮」自相矛盾 | `max_rounds` 是**计划**轮数不是硬上限，文案却按硬上限写 | 辩超了写「第 8 轮 / 计划 4 轮」，结束后报实际轮数 |

同一根因的另两处也一并修了：暂停后「点上方『继续』」够不着、以及「已结束但没复盘」的死胡同。

**改动文件**：`web/src/pages/DebateRoomPage.tsx`、`web/src/features/debate/DebateComposer.tsx`、
`web/src/features/debate/RoomHeader.tsx`、`docs/方案对照表.md`

**生产验证 8/8**（无头浏览器 390×844，复刻同构的 `8/4` 房间）：按钮在首屏视口内 `y=592`、
刷新后仍在、点击 46.5s 出复盘卡片、零 JS 错误。验收用的临时账号与房间已删除。

**这条修复已被真实使用验证**：09-26 13:06 房间 2 结束并生成复盘卡片 —— 就是你点的那一下。

## 5. ⚠️ 域名被阿里云拦截（10-02 发现）

### 现象

| 访问方式 | 结果 |
|---|---|
| `https://duijing.xyz/` | TLS 握手被重置 |
| `http://duijing.xyz/` | 403，页面标题 `Non-compliance ICP Filing`，`Server: Beaver` |
| 裸 IP 直连 `https://<服务器IP>/` | ✅ 200 正常（证书告警，浏览器需手动允许） |

**服务器本身完全正常**：FastAPI `127.0.0.1:3000` 返回 200、Nginx 本机返回 200、
`systemctl is-active duijing nginx` 都是 active、证书 12-25 到期。

判断依据：拦截是**按域名（SNI/Host）做的**，裸 IP 不受影响 → 是备案拦截，不是服务故障。

> `deploy/DEPLOY.md` §10.5 早就预言过这件事：「阿里云可能随时启用拦截」。

### 三条路

1. **走 ICP 备案**（正规做法）：约 1–3 周，需要主体信息 + 核验
2. **换非标准端口**（当天可用）：例如 8443。阿里云一般只拦 80/443。
   需要在**阿里云控制台安全组放行该端口**（目前只开了 22/80/443），
   然后 nginx 加一个同样配置的 server 块、复用现有证书即可
3. **换香港/境外节点**：不需要备案，但要重新买机器、重新部署

## 6. 部署与运维

**服务器**：阿里云 ECS，Ubuntu 24.04，应用目录 `/opt/duijing`，运行用户 `app`。
公网 IP 即 `duijing.xyz` 的解析结果。

**服务**：
```bash
systemctl status duijing nginx     # 应用与网关
journalctl -u duijing -f           # 看日志
ss -lntp | grep 3000               # 确认在监听
curl -s 127.0.0.1:3000/api/health  # 期望 status=ok、database=ok、ai.mode=hybrid
```

**发布新版本**（前端）：
```bash
cd web && npm run build            # 必须先过 tsc --noEmit
rsync -a --delete dist/ <服务器>:/var/www/duijing/dist/
```
后端改动则 `git pull` 后 `systemctl restart duijing`。

**备份**：`/var/backups/duijing/duijing-YYYY-MM-DD.db`，每日 06:25。
用的是 SQLite `.backup`（在线安全备份，不锁库）。**恢复没演练过（见 §4.5）**。

**健康检查**：`/etc/cron.d/duijing-health`，每 5 分钟跑一次 `deploy/check-health.sh`。

**排错顺序**（照 `deploy/DEPLOY.md` §10.5）：站点打不开时先 `curl 127.0.0.1` 和
`systemctl status duijing`。**本机通、外网不通 → 先查备案，不要急着重装服务。**

## 7. 验收怎么跑

**后端测试**（160 项）：
```bash
pip install -r requirements-dev.txt
pytest -q
```

**端到端**（无头浏览器，跑真实站点）：
```bash
cd e2e && npm install && npx playwright install chromium
DJ_INVITE=<邀请码> node e2e/accept.mjs      # 冷启动验收
DJ_INVITE=<邀请码> node e2e/gaps.mjs        # 方案缺口验收
node e2e/overflow-probe.mjs /debates/1      # 横向溢出探针
```
变量清单与各脚本职责见 `e2e/README.md`。

> ⚠️ **跑完必须清理测试账号。** 注册类脚本会在**生产库**里建真实账号和辩论房。
> 删的时候只删测试账号、绝不碰 `user_id=1`，并且要单独清孤儿行（SQLite 外键级联不总生效）。
> `e2e/README.md` 里有现成的 SQL。
